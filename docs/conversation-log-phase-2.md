## Conversation 13 - Logic Group Publication Safety

A read-only Builder audit found that a rejected Candidate Logic Group could release its already approved members into ordinary confirmed Clusters, allowing the rejected relationship to become an accidental publication bypass. Version `0.6.7` blocks all group states: proposed groups await review, confirmed groups await a production logic contract, and rejected groups require a separate reviewed member-resolution path. Group blockers are aggregated once per stable group ID before Cluster processing, so Cluster blockers no longer hide them. Synthetic regressions cover both logic operators, every status, partial and separate Cluster membership, deterministic diagnostics, and Draft persistence boundaries. No private artifact was changed, no real review or prevalence was performed, and member release, Catalog publication, and Role Recommendation remain unimplemented.

## Conversation 16 - Provider JSON Compatibility

A real compatible-Provider run returned malformed JSON twice while leaving the Profile and output directory unchanged. Version `0.7.1` keeps that strict failure boundary and improves the request path: OpenAI uses Responses JSON Schema, while Bailian and custom compatible endpoints use Chat Completions JSON object mode with a complete schema prompt. A Provider may fall back to prompt-only JSON only when it explicitly rejects JSON mode. Parsing accepts one valid object, one complete JSON fence, or one uniquely balanced wrapped object; it never guesses repairs for invalid syntax. The second and final attempt includes the original task, schema, and prior safe error. Optional diagnostics save only redacted hashes, lengths, modes, and errors, never raw output or credentials. All 574 synthetic tests passed without network access or real Profile data, and recommendation scoring and later Phase boundaries did not change.
